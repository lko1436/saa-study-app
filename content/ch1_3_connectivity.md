# 🌉 1-3 道路建設：如何連通你的秘密基地？

當你的基地（VPC）蓋好了，接下來要解決的是「交通問題」。你需要跟外面的公司（地端機房）連線，或是跟別人的基地連線。

---

### 1. 基地連辦公室：你要蓋大馬路還是專用地下道？

想像你要從「土城辦公室」搬資料到「AWS 基地」：

* **Site-to-Site VPN (走一般大馬路)：**
    * **邏輯：** 透過網際網路（Internet）建立一條加密隧道。
    * **比喻：** 就像是在公用馬路上派一台保鏢車護送。雖然加密了，但如果路（Internet）塞車，你的速度就會慢。
    * **考點：** **便宜、快（幾分鐘搞定）**，適合緊急用或小公司。
* **Direct Connect / DX (專屬地下道)：**
    * **邏輯：** 找電信商拉一條實體光纖，直接插進 AWS 的機房。
    * **比喻：** 為了你專門挖一條私人地下道。不管路面上（Internet）怎麼塞車，你的地下道永遠暢通。
    * **考點：** **貴、慢（施工要幾週）**，但**頻寬最大、延遲最低、最穩定**。



---

### 2. 基地連基地：天橋還是轉運大站？

如果你在雲端有好幾個基地（VPC A, B, C...）：

* **VPC Peering (一對一天橋)：**
    * **邏輯：** 讓兩邊的私有 IP 像在同一個網域一樣互通。
    * **致命限制：** **不支援「借過」 (Transitive Routing)**。
    * **場景：** 如果 A 連 B，B 連 C。A 是不能透過 B 去連 C 的。你要嘛 A 跟 C 再蓋一座橋，要嘛改用下一個方案。
* **Transit Gateway (中央轉運站)：**
    * **邏輯：** 一個星狀的集線器。所有基地、所有 VPN、所有專線都連到這。
    * **比喻：** 就像台北車站。你想去哪，只要連進北車就能轉乘到各站，不用蓋一堆點對點的天橋。
    * **考點：** **連接數十、數百個 VPC 的首選**。



---

### 3. 不走大門的秘密小徑：VPC Endpoints

如果你在基地裡想去「雲端公共倉庫 (S3)」拿檔案，但老闆規定**不能經過 Internet**（因為太危險或太貴）：

* **Gateway Endpoint (圍牆開門)：**
    * **支援對象：** 只有 **S3** 與 **DynamoDB**。
    * **特點：** **免費**。像是在基地圍牆直接挖一個洞，伸手就能拿到隔壁倉庫的東西。
* **Interface Endpoint (基地內裝電梯)：**
    * **支援對象：** 幾乎所有 AWS 服務。
    * **特點：** **要錢 (按流量收費)**。像是在你房間裡裝一台私有電梯直達目的地。

### 📝 隨堂小測驗
**Q：你的公司有 50 個 VPC 需要互相連線，且還有一條專線 (DX) 連回辦公室。如果你不想讓網路路由變得跟蜘蛛網一樣複雜，你該用什麼？**

<details>
<summary><b>點擊查看答案</b></summary>
<b>答案：Transit Gateway</b>。<br>
當連線對象一多，Peering 就會變得很混亂。Transit Gateway 能把這 50 個 VPC 全部集中管理，是大型企業架構的標準答案。
</details>

---

### ✍️ 筆記本重點摘要

1.  **連線選擇 (對比記憶)：**
    * **VPN** = 便宜/走公網/不穩。
    * **Direct Connect (DX)** = 貴/實體專線/極穩。
2.  **跨 VPC 管理：**
    * **Peering** = 一對一，不能「借過」 (A-B-C 不通 A-C)。
    * **Transit Gateway** = 中心化，管理多個 VPC 首選。
3.  **秘密通道 (Endpoints)：**
    * **Gateway 型** = **免費** (僅限 S3/DynamoDB)。
    * **Interface 型** = **付費** (其他大多數服務)。

4.  **考試直覺 (關鍵字)：**
    * 看到「極度穩定、不走 Internet」 ➔ **Direct Connect**。
    * 看到「連接數十個 VPC」 ➔ **Transit Gateway**。
    * 看到「不想走 Internet 存取 S3 且要省錢」 ➔ **Gateway Endpoint**。
